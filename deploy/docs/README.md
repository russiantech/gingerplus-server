# Southern Rose — cPanel Deployment (`/deploy`)

Gunicorn + Supervisor for the API, static hosting for the storefront. One config file drives everything.

| Part | Where | URL |
|------|-------|-----|
| API (FastAPI) | `/home/gingerpl/api.gingerplus.ng` | https://api.gingerplus.ng |
| Storefront + admin (React build) | `/home/gingerpl/public_html` | https://gingerplus.ng |

## File structure (API)

```
/home/gingerpl/api.gingerplus.ng/
├── deploy/
│   ├── config.env          ← EDIT THIS (single source of truth)
│   ├── deploy.sh           ← One-time setup
│   ├── control.sh          ← Daily ops (start/stop/restart/logs/health)
│   ├── ci.sh / release.sh  ← Pull → install → migrate → restart
│   ├── redeploy.sh         ← Hard redeploy
│   ├── monitor.sh          ← Cron health check
│   ├── recovery.sh         ← Emergency recovery
│   ├── selfheal.sh         ← Optional 20s watchdog (install_selfheal.sh)
│   └── gunicorn.conf.py    ← Generated by deploy.sh
├── index.py                ← ASGI entrypoint (index:app)
├── app/  alembic/  requirements.txt
├── .env                    ← Secrets (chmod 600)
└── logs/
```

## 1. API (api.gingerplus.ng)

```bash
# cPanel → Setup Python App: Python 3.11, App root api.gingerplus.ng, domain api.gingerplus.ng
# Upload the contents of server/ into /home/gingerpl/api.gingerplus.ng
source /home/gingerpl/virtualenv/api.gingerplus.ng/3.11/bin/activate && cd /home/gingerpl/api.gingerplus.ng
pip install -r requirements.txt
cp .env.example .env && chmod 600 .env && nano .env     # see ENV_VARIABLES_GUIDE.md
alembic upgrade head                                    # create tables
python -m app.db.init_db                                # seed content + admin (first deploy only)
bash deploy/deploy.sh                                   # writes configs, starts Gunicorn under Supervisor
```

Then route the subdomain to Gunicorn. In `/home/gingerpl/api.gingerplus.ng/.htaccess` (or the subdomain document root):

```apache
RewriteEngine On
RewriteRule ^(.*)$ http://127.0.0.1:8001/$1 [P,L]
```

(Port must equal `PORT` in `config.env`. If your host does not allow `[P]`, ask support to enable `mod_proxy` or use their "Application Manager" reverse-proxy.)

Check: `curl https://api.gingerplus.ng/health` → `{"status":"ok",...}`

## 2. Storefront (gingerplus.ng)

Build on your computer (Node 18+), then upload:

```bash
cd client
npm ci
npm run build          # reads .env.production → VITE_API_URL=https://api.gingerplus.ng
```

Upload **the contents of `client/dist/`** (including the hidden `.htaccess`) to `/home/gingerpl/public_html/`. Done — the `.htaccess` handles HTTPS, `www` → bare domain, SPA routing, compression and long-term caching.

## 3. Operate

```bash
bash deploy/control.sh status | logs | logs-err | restart | graceful | health | workers | shell
bash deploy/release.sh                       # git pull → pip install → alembic → restart
*/5 * * * * bash /home/gingerpl/api.gingerplus.ng/deploy/monitor.sh      # crontab -e
bash deploy/install_selfheal.sh              # optional: faster watchdog
```

Release without git (zip upload): upload files, then
`pip install -r requirements.txt && alembic upgrade head && bash deploy/control.sh restart`.
